# Итоговая проверка и завершение

Часть `superpowers:subagent-driven-development`. Все задачи плана выполнены. Применяй СУИИР, прямые указания пользователя и ограничения среды; использование субагентов и моделей должно быть разрешено.

Для проверки всей ветки также нужен пакет: выполни `bash scripts/review-package PLAN_FILE MERGE_BASE HEAD` по абсолютному пути из рабочего дерева. MERGE_BASE — коммит, от которого началась ветка, например результат `git merge-base main HEAD`. В запросе итоговому проверяющему укажи выведенный путь: он прочитает один файл вместо самостоятельного построения diff. Исходный навык предлагает наиболее способную доступную модель; см. выбор моделей в SKILL.md. Используй шаблон [code-reviewer.md](../../requesting-code-review/code-reviewer.md) из `superpowers:requesting-code-review`. Передай ссылки на отложенные незначительные и приостановленные замечания в журнале, чтобы проверить, какие нужно исправить до слияния.

Если итоговая проверка нашла проблемы, передай полный список ОДНОМУ субагенту исправлений, а не отдельному исполнителю на каждое замечание. Отдельные исполнители каждый раз восстанавливают контекст и запускают тесты; однажды итоговая волна исправлений обошлась дороже всех задач вместе. Затем проведи ровно одну ограниченную повторную проверку этой волны: запусти `bash scripts/review-package PLAN_FILE FIX_BASE HEAD` по абсолютному пути из рабочего дерева для диапазона исправлений и используй [re-review-prompt.md](../re-review-prompt.md).

Оставшиеся замечания разрешай по правилу ограничения цикла исправлений: [references/fix-loop.md](fix-loop.md). Либо отложи их с записанным решением, либо прими решение по критически важным и запиши его. Действуют условия остановки из начала SKILL.md с учётом уже предоставленного разрешения пользователя. Вторая волна исправлений исходным процессом не предусмотрена: оставшиеся важные замечания сообщаются пользователю при завершении ветки.

## Завершение

До удаления чего-либо собери все строки журнала с `Ruling:` — решения предварительной проверки, отложенные замечания и решения на пределе исправлений. Перечисли их в итоговом сообщении в разделе «Мои решения» по порядку принятия и укажи цену возможной ошибки. Список должен быть полным: каждое решение из журнала попадает в него. Так пользователь узнаёт о решениях, принятых от его имени; решение, исчезнувшее вместе с рабочей областью, было бы скрытым.

Когда итоговая проверка всей ветки чистая, а исправления объединены, исходный процесс предлагает удалить рабочую область плана командой `rm -rf <workspace>`: записью остаётся история git. Соседние каталоги принадлежат другим планам, не затрагивай их. До удаления соблюдай СУИИР и необходимость разрешения на уничтожение данных; если оно не получено, сохрани файлы.

Используй `superpowers:finishing-a-development-branch`.
