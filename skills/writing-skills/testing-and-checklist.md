# Проверка и выпуск навыка

Соблюдай приоритет СУИИР и инструкций пользователя, описанный в основном файле навыка.

## Проверка разных типов навыков

Для разных навыков нужны разные методы.

### Навыки соблюдения правил и требований

**Примеры:** TDD, verification-before-completion, designing-before-coding.

**Проверяй:** теоретическими вопросами на понимание правил; сценариями давления на соблюдение; сочетаниями давления времени, потраченных усилий и усталости. Выявляй оправдания и добавляй явные контраргументы.

**Критерий успеха:** агент соблюдает правило при максимальном давлении.

### Навыки-техники

**Примеры:** condition-based-waiting, root-cause-tracing, defensive-programming.

**Проверяй:** сценариями применения техники, вариациями и крайними случаями, тестами на недостаток информации и пробелы инструкции.

**Критерий успеха:** агент правильно применяет технику в новой ситуации.

### Навыки-модели мышления

**Примеры:** reducing-complexity, information-hiding.

**Проверяй:** распознаёт ли агент применимость модели, умеет ли применить её и понимает ли по контрпримерам, когда её применять НЕ следует.

**Критерий успеха:** агент правильно определяет, когда и как применять модель.

### Справочные навыки

**Примеры:** документация API, справочники команд и библиотек.

**Проверяй:** находит ли агент информацию, корректно ли применяет её и покрыты ли распространённые случаи.

**Критерий успеха:** агент находит и правильно использует справочные сведения.

## Оправдания отказа от тестирования

| Оправдание | Реальность |
|---|---|
| «Навык и так понятен» | Понятно тебе ≠ понятно другим агентам. Проверь. |
| «Это только справочник» | В нём тоже бывают пробелы и неясности. Проверь поиск сведений. |
| «Проверка избыточна» | У непроверенных навыков бывают проблемы; короткая проверка может сэкономить часы. |
| «Проверю, если возникнут проблемы» | Проблема означает, что агент не умеет пользоваться навыком. Проверяй ДО установки. |
| «Слишком утомительно проверять» | Отлаживать плохой навык в работе ещё утомительнее. |
| «Я уверен, что всё хорошо» | Уверенность не заменяет проверки. |
| «Достаточно теоретического обзора» | Чтение ≠ применение. Проверь на сценариях. |
| «Нет времени на проверку» | Непроверенный навык может потребовать больше времени на исправление потом. |

Все эти оправдания указывают на необходимость проверить навык перед установкой.

## Подбирай форму под ошибку

До написания инструкции классифицируй исходную ошибку. Форма, хорошо устраняющая одну ошибку, может ухудшить другую.

| Исходная ошибка | Подходящая форма | Неподходящая форма |
|---|---|---|
| Нарушает правило под давлением, хотя знает его | Запрет, таблица оправданий и тревожные признаки; см. references/bulletproofing.md | Мягкие советы «желательно», «рассмотри» |
| Правило соблюдает, но результат неправильной формы: раздутый запрос, скрытый вывод, пересказ спецификации | Положительный рецепт или договорённость: из каких частей и в каком порядке состоит результат | Список запретов «не пересказывай», «не рассказывай» |
| Пропускает обязательный элемент того, что уже создаёт | Структура: обязательное поле или место в заполняемом шаблоне | Текстовое напоминание рядом с шаблоном |
| Поведение зависит от условия | Условие с наблюдаемым признаком: «если краткое задание существует, сошлись на него» | Безусловное правило с оговорками об исключениях |

**Почему запреты могут мешать формированию результата:** при конкурирующем стимуле — например, «сделать запрос самодостаточным» — агенты пытаются договориться с запретом. В сравнительных тестах формулировок указаний для делегирования вариант с запретами производил больше нежелательного содержания, чем вариант с рецептом, и имел тенденцию быть хуже даже отсутствия указаний. Проверяй свой случай микротестом вместо предположений и не выбирай запрет автоматически. Рецепт задаёт проверяемую форму результата.

**Правила для любой формы:**
- **Без расплывчатых оговорок.** «Не делай X, если это не важно» заново открывает возможность обхода. В описанных тестах одна такая оговорка сделала устойчивую инструкцию нестабильной. Реальное исключение выражай отдельным условием с наблюдаемым признаком.
- **Оговорки об исключении не задают границы.** Фраза «ограничение не относится к блокам кода» всё равно может подавлять блоки кода. Если часть результата должна быть исключена, перестрой правило так, чтобы оно на неё не распространялось.

## Защита от оправданий

Если исходная проблема — нарушение дисциплины, до написания инструкции прочитай [references/bulletproofing.md](references/bulletproofing.md): закрытие лазеек, смысл и буква правила, таблица оправданий и тревожные признаки.

## RED–GREEN–REFACTOR для навыков

### RED: падающий тест и исходное состояние

Выполни сценарий давления с субагентом БЕЗ навыка. Запиши точное поведение:
- Какие решения были приняты?
- Какие оправдания прозвучали дословно?
- Какое давление вызвало нарушения?

Это аналог наблюдения падения теста: перед написанием навыка нужно увидеть естественное поведение агента.

### GREEN: минимальный навык

Напиши навык, устраняющий конкретные выявленные оправдания. Не добавляй материал для гипотетических ситуаций.

Запусти те же сценарии С навыком. Теперь агент должен соблюдать правила.

### REFACTOR: закрытие лазеек

Агент нашёл новое оправдание? Добавь явное противодействие. Повторяй проверку до устранения лазеек.

### Микротест формулировок до полных сценариев

Полные сценарии давления — итоговая проверка, но каждый прогон дорог и долог. Сначала проверь формулировку:

1. **Один пример со свежим контекстом на вызов:** прямой API-вызов либо однократный субагент при отсутствии API. Системный запрос содержит реальный контекст будущей инструкции — полный навык или шаблон запроса, а не отдельную фразу; пользовательский запрос провоцирует проверяемую ошибку.
2. **Всегда включай контроль без инструкции.** Если контроль не проявляет ошибку, исправлять нечего: остановись и не пиши инструкцию.
3. **Не менее пяти повторов каждого варианта.** Одиночный пример ненадёжен.
4. **Вручную прочитай каждое найденное совпадение.** Можно считать программно, но повтор шаблона и цитаты контрпримеров выглядят как срабатывания; автоматический счёт может завышать результат.
5. **Разброс — показатель.** При работающей формулировке результаты сходятся. Пять разных трактовок за пять попыток означают, что правило недостаточно определённо; уточни форму, прежде чем добавлять текст.

Микротесты проверяют формулировки, но не заменяют сценарии давления для навыков дисциплины.

**Методика:** [references/testing-skills-with-subagents.md](references/testing-skills-with-subagents.md) описывает сценарии давления, типы давления — время, потраченные усилия, авторитет, усталость, — систематическое закрытие лазеек и метатестирование.

## Антипаттерны

### ❌ Рассказ о конкретном случае
«В сессии 2025-10-03 мы обнаружили, что пустой projectDir вызвал…»

**Почему плохо:** слишком частный и непереносимый пример.

### ❌ Распыление на много языков
`example-js.js`, `example-py.py`, `example-go.go`.

**Почему плохо:** среднее качество и нагрузка на поддержку.

### ❌ Код внутри блок-схемы
```dot
step1 [label="import fs"];
step2 [label="read file"];
```
**Почему плохо:** сложно читать и невозможно удобно скопировать.

### ❌ Общие названия
`helper1`, `helper2`, `step3`, `pattern4`.

**Почему плохо:** названия должны передавать смысл.

## СТОП: перед следующим навыком

Исходный процесс требует после написания ЛЮБОГО навыка остановиться и завершить процесс выпуска.

**Не следует:** создавать много навыков без проверки каждого; переходить к следующему до проверки текущего; пропускать проверку под предлогом эффективности пакетной работы.

Следующий контрольный список обязателен для каждого навыка. Выпуск непроверенного навыка сопоставим с выпуском непроверенного кода. Выполняй доступные проверки и сообщай об ограничениях; учитывай инструкции пользователя и среды.

## Контрольный список создания навыка

**ВАЖНО:** создай отдельную задачу для КАЖДОГО пункта.

**RED — падающий тест:**
- [ ] Создать сценарии давления: для навыков дисциплины сочетать не менее трёх факторов.
- [ ] Выполнить сценарии БЕЗ навыка, дословно записать исходное поведение.
- [ ] Найти закономерности оправданий и ошибок.

**GREEN — минимальный навык:**
- [ ] В имени только буквы, цифры и дефисы, без скобок и спецсимволов.
- [ ] YAML frontmatter с обязательными `name` и `description` — не более 1024 символов; см. [спецификацию](https://agentskills.io/specification).
- [ ] Description начинается с «Используй, когда…» и включает конкретные признаки.
- [ ] Description написано от третьего лица.
- [ ] По всему тексту есть ключевые слова для поиска: ошибки, признаки, инструменты.
- [ ] Есть понятный обзор с основным принципом.
- [ ] Исправлены конкретные исходные нарушения, обнаруженные на этапе RED.
- [ ] Форма указаний соответствует типу ошибки.
- [ ] Для инструкций, формирующих поведение, проведены микротесты формулировки с контролем без указаний: минимум пять повторов и ручная проверка всех совпадений; для чисто справочных навыков неприменимо.
- [ ] Код находится внутри навыка либо есть ссылка на отдельный файл.
- [ ] Есть один отличный пример, а не варианты на разных языках.
- [ ] Сценарии выполнены С навыком и показали соблюдение правил.

**REFACTOR — закрытие лазеек:**
- [ ] Выявлены НОВЫЕ оправдания при проверке.
- [ ] Добавлены явные контраргументы, если навык обеспечивает дисциплину.
- [ ] Составлена таблица оправданий по всем итерациям.
- [ ] Создан список тревожных признаков.
- [ ] Проведена повторная проверка.

**Качество:**
- [ ] Небольшая блок-схема используется только при неочевидном решении.
- [ ] Есть краткая справочная таблица.
- [ ] Есть раздел типичных ошибок.
- [ ] Нет повествования ради рассказа.
- [ ] Вспомогательные файлы используются только для инструментов или объёмных справочников.

**Выпуск:**
- [ ] Навык закоммичен в git и отправлен в свою копию, если она настроена.
- [ ] Рассмотрен вклад через PR, если навык полезен широко.

## Как агент найдёт навык

1. **Столкнётся с проблемой:** например, нестабильные тесты.
2. **Поищет навыки:** проверит описания и категории.
3. **Найдёт SKILL:** описание соответствует задаче.
4. **Просмотрит обзор:** определит применимость.
5. **Прочитает приёмы:** воспользуется справочной таблицей.
6. **Загрузит пример:** только когда дойдёт до реализации.

Оптимизируй навык под этот путь: размещай поисковые термины ближе к началу и повторяй там, где они нужны.
