# История выпусков Superpowers

## v7.0.2 (2026-11-03)

Этот выпуск продолжает настройку вопросов brainstorming. Навык задаёт их реже, начинает с выяснения причины и при наличии выбора предлагает варианты. Также исправлены проблемы начальной загрузки в шести средах, а вспомогательные скрипты SDD и executing-plans надёжнее защищены от работы с неправильным репозиторием или задачей.

### Brainstorming

- **Вопрос задаётся только тогда, когда ответ изменит результат работы и его нельзя получить из имеющихся данных.** Иначе навык предлагает собственное решение, которое можно поправить. Он также перестаёт спрашивать о процессе: оформление, место файлов, необходимость дополнительного изучения и способ показа результата выбирает сам и сообщает о решении. (#2644)
- **Если вы не объяснили причину запроса, сначала выясняется именно она.** Вопрос открытый, без предложенных вариантов ответа. (#2644)
- **Когда доступны конкретные варианты выбора, навык показывает их и рекомендует один.** В тесте, где спецификация назначала Ctrl+K двум функциям, версия 7.0.1 всегда обнаруживала конфликт, но во всех восьми запусках просто спрашивала «какой вариант?». Новый выпуск во всех восьми случаях показывал варианты и рекомендацию. (#2644)
- **По формулировке запроса навык определяет, хотите ли вы обсуждать технические решения.** Если в запросе ничего не осталось открытым, первое сообщение содержит краткий проект для согласования. (#2644)
- В тестовых разговорах со слепой оценкой число лишних вопросов снизилось с 41 в версии 7.0.1 до 23; причина запроса выяснялась до предложения подхода во всех 33 разговорах против 28 ранее; случаев начала реализации до согласования не было против четырёх ранее. По сравнению с brainstorming версии 6.4.2 в тех же сценариях стало меньше лишних вопросов — 23 против 34, причина выяснялась чаще — 33/33 против 19/33, а результат по отсутствию реализации до согласования совпал. (#2644)
- **`start-server.sh --project-dir .` теперь работает.** Скрипт переходил через `cd` в собственный каталог до запуска сервера, поэтому относительный `--project-dir` разрешался неправильно и сервер не запускался. Теперь путь определяется заранее. Спасибо @anchore-jesset за сообщение. (#2524, #2608)

Спасибо @mbcrawfo и всем участникам #2530 за стенограммы и тестирование 7.0.1. Если brainstorming всё ещё задаёт неуместный вопрос, сообщите об этом там, указав свой запрос и ответный вопрос.

### Хуки

- **Copilot в Windows теперь получает начальную загрузку.** Copilot CLI и Copilot в VS Code выполняют команды хуков через PowerShell, который отклонял команду SessionStart с ParserError. В `hooks.json` добавлена форма команды для `powershell`. Спасибо @ronpieper-engcp и @orty за сообщения. (#2189, #1225, #2592)
- **Хук SessionStart больше не запускает дочерние процессы.** В Git Bash каждый процесс занимает десятки миллисекунд; раньше хук создавал шесть при каждом запуске, `/clear` и сжатии контекста. Спасибо @midirectiekade14-debug за сообщение и измерения. (#2081, #2593)
- **В Unix без bash `run-hook.cmd` использует zsh или тихо завершает работу.** Раньше он возвращал код 127 с `bash: not found`, и начальная загрузка терялась. (#2503, #2594)

### Pi

- **Начальная загрузка теперь передаётся с каждым запросом.** Расширение отключало её после первого запроса сеанса; все последующие оставались без неё. Поскольку первое сообщение запроса менялось, кеширование запросов Anthropic также переписывало весь кеш разговора на втором запросе. По дневным измерениям @sjawhar, это происходило в 83% переходов от первого запроса ко второму. Спасибо @DKnight927 за сообщение. (#2083, #2595)
- **Фильтр `skills` в записи пакета Superpowers работает.** Расширение повторно добавляло весь каталог `skills/` после применения фильтра pi, поэтому даже `"skills": []` загружал все 15 навыков. Спасибо @adrian-85 за сообщение и @m2dumpling за исправление. (#2394, #2402, #2598)

### Hermes Agent

- **Субагенты `delegate_task` больше не получают начальную загрузку контроллера.** Каждый дочерний агент начинал с пустой историей и воспринимался как новый сеанс, поэтому получал полную загрузку; некоторые начинали с `using-superpowers` вместо выполнения задачи. Спасибо @thealps01-netizen за сообщение. (#2536, #2596)

### OpenCode

- **Начальная загрузка предписывает использовать идентификаторы навыков без пространства имён.** OpenCode регистрирует `brainstorming`, а не `superpowers:brainstorming`; модель, копировавшая полную форму, получала «навык не найден» и продолжала без него. Спасибо @shiluoluo16 за сообщение. (#2583, #2597)
- **Запрос с упоминанием `EXTREMELY_IMPORTANT` больше не отключает начальную загрузку.** Плагин считал её уже присутствующей, если первое сообщение содержало это слово; простой вопрос о таком блоке в контексте приводил к пропуску загрузки. Теперь проверяется собственная первая строка загрузки. Спасибо @Swift22 за сообщение. (#2197, #2600)
- **Запросы OpenCode 2 на сжатие контекста и генерацию содержат начальную загрузку.** Раньше без неё запрос сжатия, крупнейший в сеансе, не попадал в кеш запросов. Спасибо @tpischke за сообщение и измерения. (#2391, #2601)

### Muse

- **Хук SessionStart запускается в Debian и Ubuntu.** Манифест Muse вызывал bash-скрипт `hooks/session-start` через `sh`. Там, где `sh` — это dash, хук завершался с кодом 2 и начальная загрузка не выполнялась. Теперь используется `bash`. Спасибо @rahul05ranjan за сообщение и @twotnguyen за исправление. (#2528, #2533)

### Разработка с субагентами и выполнение планов

- **Вспомогательные скрипты работают с репозиторием текущего каталога, как `git`, и принимают `-C DIR` для другого.** Вне репозитория `sdd-workspace` раньше записывал рабочую папку в текущий каталог агента, часто в кеш плагина. Теперь все пять скриптов завершаются с кодом 2 и пояснением необходимых действий. В новом проекте без коммитов агенту понадобятся `git init` и первый коммит. `-C` также позволяет контроллеру проверить рабочую копию без префикса `cd … ;`, который Claude Code не может добавить в разрешённый список. Спасибо @abat-kek, @rz1989s и @jiyimeta за сообщения. (#2429, #2242, #1799, #2606)
- **Навыки предписывают запускать вспомогательные скрипты по абсолютному пути из рабочей копии.** Раньше указывалось «из каталога навыка», из-за чего агенты переходили туда через `cd` и запускали скрипты на файлах самого плагина. Теперь тест выявляет относительные пути к скриптам в навыках. Спасибо @anchore-jesset за сообщение. (#2525, #2607)
- **`task-brief` распознаёт идентификаторы задач `A1`, `6b`, `2.1` и подобные.** Раньше идентификаторы с первой буквой отклонялись, а запрос задачи 6 также выбирал 6b. Если заголовки плана не на английском, скрипт сообщает, что необходимо слово `Task`, и показывает найденные заголовки. Спасибо @rhuthik, @jnrod03-rgb, @christopherpconway и @ferrous26 за сообщения. (#2459, #2496, #2175, #2405, #2604)
- **`task-brief` отклоняет задание, которое из-за незакрытого блока кода растянулось до конца плана.** Отсутствующая закрывающая граница скрыла все последующие заголовки, и задача из 177 строк вернулась как задание на 1159 строк с пятью задачами. Спасибо @bobbykim89 за сообщение. (#2436, #2605)
- **В Windows скрипты выводят пути, открываемые PowerShell.** Раньше выдавался `/c/Users/…`, который PowerShell воспринимает как `C:\c\Users\…`. Спасибо @sean-parent за сообщение. (#2307, #2602)

### Систематическая отладка

Вы должны выбрать и действовать», устанавливались рядом с `SKILL.md` и могли попасться агенту во время работы. Теперь они находятся в `tests/`, а тест не допускает подобных файлов ни в одном навыке. Спасибо @Caarles00 за сообщение. (#2277, #2654)

## v7.0.1 (2026-10-21)

Выпуск перенастраивает brainstorming после переработки в v7.0.0. Многие справедливо отметили, что новые стандартные вопросы быстро надоедают и звучат шаблонно. Теперь навык изучает контекст до вопросов и старается задавать их точнее. Авторы планируют продолжать настройку.

Также сокращены три длинных навыка, чтобы они лучше сохранялись при сжатии контекста Claude Code. Шаблоны issue и PR теперь запрашивают резюме, написанное человеком.

### Brainstorming

- **Сначала изучается контекст.** В существующем проекте или при указании спецификации, плана или файлов навык читает их до первого сообщения и не спрашивает о том, что уже известно из материалов. (#2560)
- **Вопросы стали точнее.** В v7.0.0 каждый сеанс начинался одинаково: предложение пропустить вопросы, затем общий вопрос о «моменте, когда вам этого не хватило». Теперь, если вы уже описали пожелание, навык пересказывает запрос с учётом найденного в проекте и спрашивает об одном оставшемся открытом вопросе. Последующие вопросы учитывают ответы и найденные данные и объясняют, что изменит ответ. (#2560, #2571)
- **Предложение пропустить вопросы показывается только при самостоятельном запуске навыка.** Если вы назвали brainstorming или использовали `/brainstorming`, он больше не предлагает отказаться от него. (#2560)
- **До реализации навык представляет подходы и пишет проектный документ.** Он предлагает два или три способа, рекомендует один и просит выбрать. Затем создаёт документ — краткий для небольшого изменения — и не начинает реализацию до согласования. Ранее некоторые пользователи видели пропуск документа: в тестовом сценарии до изменения это происходило во всех 24 запусках без вопроса, после — в трёх из 24. (#2571)

Спасибо @mbcrawfo за создание #2530, а также @katyatitkova, @ertra, @blorenz, @Biomaj, @fsalum, @technicalpickles, @orochi235, @alexxburg, @fcavalieri, @CelesteCunha и @zzzzz9999 за сообщения, стенограммы и тестирование.

Если вопросы brainstorming в 7.0.1 всё ещё кажутся неудачными, оставьте комментарий в #2530. Наиболее полезны примеры: ваш запрос, ответный вопрос и то, что вы хотели бы услышать.

### Навыки лучше сохраняются при сжатии контекста Claude Code

После сжатия Claude Code повторно прикрепляет каждый навык, обрезая его на 20 000 символах; всё после этой границы теряется до конца сеанса. В одном сообщённом случае subagent-driven-development потерял ограничение в пять раундов и выполнил 18 раундов исправлений одной задачи. Спасибо @dan-1492 за сообщение. (#2481)

- **`subagent-driven-development`** переносит инструкции о цикле исправлений, итоговом ревью, обработке отчётов, возобновлении, предварительной проверке, объединении действий и невозможности проверки в `references/`. Каждый файл читается с диска на нужном этапе. (#2565)
- **`writing-skills`** переносит вспомогательные документы: шаблон SKILL.md и инструкции по обнаружению, защите от ошибок и соглашениям для схем — в `references/`. (#2564)
- **`executing-plans`** удаляет пример процесса, повторявший уже изложенные правила. (#2563)
- `tests/skill-size/test-skill-size.sh` выдаёт ошибку, если какой-либо `SKILL.md` достигает 20 000 байт. (#2565)

### Участие в разработке

- **Шаблоны issue и PR теперь спрашивают, кто подаёт обращение, что попросил человек-партнёр, и запрашивают написанное человеком резюме до 200 слов.** Отчёт об ошибке также спрашивает, как подтверждено отсутствие проблемы без Superpowers. (#2569)
- **PR, написанные агентом для исправления чужой задачи, не принимаются без просьбы сопровождающего.** Если человек-партнёр столкнулся с той же проблемой, добавьте его сообщение в существующую задачу. Это указано в шаблоне PR, `AGENTS.md` и README. (#2569)
- **`diagnosing-superpowers` добавляет те же два раздела в черновики issue** и не отправляет их, пока резюме является заглушкой. Предзаполненная ссылка теперь открывает шаблон Bug Report; шаблон Session Diagnosis Report удалён. (#2569)

## v7.0.0 (2026-10-09)

Brainstorming переработан с нуля, чтобы лучше выполнять своё назначение: помогать выяснить и сформулировать, чего вы хотите, до начала реализации. Новый навык просит описать желаемый результат и его причины, пересказывает услышанное для исправления и задаёт вопросы, пока картина не станет ясной. Затем он подбирает процесс по масштабу работы: от непосредственного выполнения до полного проектного документа.

Выпуск также добавляет нативный манифест плагина для Antigravity Marketplace и исправляет обнаружение хуков Windows, пути Git Bash, описания навыков Hermes и другие ошибки.

### Brainstorming

- **Навык выясняет пожелания до предложения решения.** Первое сообщение предлагает пропустить вопросы и задаёт один открытый вопрос о реальной ситуации или конкретном представлении результата. Варианты выбора предлагаются только при затруднениях. Также навык предлагает изучить аналоги, проект или интернет. По мере понимания он пересказывает каждую часть в нескольких сотнях слов и помечает предположения как предположения. (#2463)
- **Масштаб определяется после выяснения пожеланий и объясняется простыми словами.** Быстрая понятная задача выполняется сразу, небольшое изменение согласуется в чате, для проекта создаётся документ. Пользователь может изменить выбранный подход; при росте сложности навык повышает масштаб. (#2463)
- **Проверка исполнителем заменяет проверяющего спецификацию.** Новый субагент читает проект как будущий исполнитель и перечисляет оставшиеся вопросы. Brainstorming отвечает на возможные самостоятельно, отмечает собственные небольшие решения и одним раундом передаёт пользователю вопросы, влияющие на итог. (#2463)
- **Навык выясняет, какие решения о способе реализации пользователь хочет принять сам.** Платформу, язык, библиотеки и формат он обсуждает при наличии предпочтений; при делегировании выбирает разумные значения и сообщает их. Это действует и при пропуске вопросов. Изменение появилось после сеанса, где проектировалось приложение iOS, но вопрос о платформе не задали и создали веб-приложение. (#2482, #2483)
- **Визуальный помощник предлагается, когда показать полезнее, чем описать:** экраны, компоновки, процессы, визуально отличающиеся варианты и схемы. Предупреждение о стоимости токенов из предложения убрано. (#2463)
- **Визуальный помощник корректно показывает экраны с `$'`, `$&` и похожими последовательностями.** Сервер вставлял содержимое через `String.replace`, воспринимавший их как шаблоны замены; теперь вставка буквальная. Спасибо @andrew-yian за сообщение и @luochen211 за исправление. (#2362, #2364)

### Antigravity

- **`agy plugin install https://github.com/obra/superpowers` устанавливает Superpowers как нативный плагин Antigravity.** Добавлен `.antigravity-plugin/plugin.json` с названием для Marketplace, логотипом и рекомендуемыми запросами. Ранее agy импортировал репозиторий как расширение Gemini CLI, а затем при каждом сеансе отклонял скопированный файл хуков формата Claude с ошибкой `invalid hook "hooks": command hook must specify 'command'`. Команда установки не меняется. (#2479)
- **Начальная загрузка Superpowers в Antigravity выполняется через обнаружение навыков.** У Antigravity нет события хука начала сеанса, но модель видит описания установленных навыков; фраза «Use when starting any conversation» побуждает её загрузить `using-superpowers`. Это проверено на agy 1.3.1 в 12 запусках: запросы «Let's make a react todo list» и «add a settings page» вызывали brainstorming до написания кода, а ошибка теста — systematic-debugging до правок. Исправлены README и руководство по переносу, описывавшие никогда не существовавшие хук начала сеанса и установочный скрипт. (#2479)

### Хуки

- **SessionStart работает, если среда запускает его с повреждённым `PATH`.** Хуки больше не ищут `dirname`, `cat` или `bash` через `PATH`, поэтому невозможность разрешить их при запуске, anthropics/claude-code#43127, больше не приводит к потере начальной загрузки. Спасибо @kannan983 за сообщение и Ada Sen за исправление. (#2310, #2349)
- **Windows: `run-hook.cmd` находит Git for Windows, установленный для пользователя, и пропускает средства запуска WSL.** Добавлена проверка `%LOCALAPPDATA%\Programs\Git`; при поиске в `PATH` пропускаются WSL-варианты `bash.exe`, не работающие без дистрибутива Linux. Спасибо @jp5247 за сообщение, @citizen204 (#1864) и @KaiyiQuan (#2365) за объединённые исправления. (#1863, #2393)
- **Windows: `run-hook.cmd` игнорирует `bash` и `where` в текущем каталоге.** Раньше репозиторий мог разместить `bash.cmd` или `where.bat`, которые запускались при начале сеанса. (#2393)
- **Windows: `run-hook.cmd` передаёт среде коды завершения хуков.** Раньше он сообщал об успехе даже при ошибке хука. (#2393)

### Разработка с субагентами

- **`sdd-workspace` не изменяет существующий `.superpowers/sdd/.gitignore` репозитория.** Раньше при каждом запуске он перезаписывался содержимым `*`, отменяя сохранённую в репозитории версию, например допускающую отслеживание журналов `progress.md`. Теперь стандартный файл создаётся только при его отсутствии. Спасибо @aruizcu1989 за исправление. (#2161, #2399)

## v6.2.0 (2026-07-23)

### Разработка с субагентами

Два структурных изменения отслеживания прогресса и закрытия замечаний ревью, разработанные с использованием реальных кампаний оценок:

- **Рабочая папка привязана к плану.** В `.superpowers/sdd/` не было идентификатора плана и завершения срока жизни: последующий план в том же рабочем дереве мог прочитать журнал предыдущего как свой. Это наблюдалось на практике с несколькими случаями смешения и ручными обходами. Теперь `sdd-workspace` требует файл плана и определяет отдельный каталог `.superpowers/sdd/<plan-basename>/`; `task-brief` и `review-package` записывают в него, причём `review-package` получает файл плана первым аргументом. Первая строка журнала называет план; после успешного итогового ревью рабочая папка удаляется, а постоянной записью остаётся история git. Исходные оценки показали, что контроллеры уже отвергали чужие журналы, но тратили 6–13 вызовов инструментов на разбор git между планами при каждом возобновлении; новая структура определяет принадлежность напрямую. Результаты 25/25 исходных и GREEN-запусков описаны в `docs/specs/` и `docs/plans/`.
- **Цикл исправлений возобновляет исполнителя.** Вместо новых запусков каждый раунд возобновляет прежнего исполнителя; добавлен ограниченный шаблон повторной проверки `re-review-prompt.md`, чтобы проверять исправления, а не перечитывать всю задачу. После пяти раундов срабатывает ограничитель и контроллер принимает решение по замечаниям. SKILL.md перестроен по жизненному циклу, а Red Flags преобразованы в принятую таблицу рационализаций.

### Навыки

Проведено сокращение по всей ветке: удалены повторения, ссылки на авторитет и рекламные описания преимуществ, адресованные уже вызвавшему навык агенту. Все необходимые аргументы перенесены в строки таблиц рационализаций или к месту применения. Каждое сокращение проверялось микротестами с субагентами; единственное измеримо ухудшившее поведение было переработано, а не выпущено.

- **`testing-anti-patterns.md` переименован в `writing-good-tests.md`.** Справочник TDD перестроен в позитивный каталог из шести правил, начинающихся с хорошего примера. Добавлен принцип проверяемости: назвать производственное изменение, из-за которого тест должен упасть; выводить ожидания независимо от проверяемого кода; завершать мутационной проверкой. Явно закрыты две ловушки: проверка присутствия строк — grep-тесты скриптов, навыков и запросов лишь имитируют проверяемость, наблюдаться должно поведение — и тест-детектор изменений, где постоянное утверждение может упасть, ничего не защищая. Для обеих предусмотрена обязательная остановка проверки. Тривиальный код и человеческий текст не требуют теста; условие применения расширено с «добавления моков» на любое написание тестов.
- **Аргументы TDD «Why Order Matters» сохранены в строках рационализаций.** Полное удаление раздела измеримо ухудшило практику написания тестов первыми при давлении «сначала код, потом тесты»: контроль 8/10 против 5/10 после удаления, подтверждено в Claude и Codex. Поэтому аргументы перенесены в Common Rationalizations и появляются там, где агент пытается оправдать нарушение порядка.
- **`finishing-a-development-branch` больше не предлагает отбросить работу.** Меню появилось, когда удаление веток было обычным делом; пункт «Discard this work» рядом с «Merge» подталкивал к уничтожению завершённой и проверенной работы. Отбрасывание остаётся доступным только по явному запросу с прежним подтверждением вводом. Одновременно создание PR стало независимым от Git-платформы: используется её CLI или URL, выведенный при отправке, вместо закрытого списка инструментов. Исправлена и ошибка: путь рабочей копии вычислялся повторно после перехода в другой каталог при очистке, поэтому проверка происхождения не совпадала и очистка незаметно пропускалась.
- **Повторы и убеждающий текст удалены из библиотеки.** `brainstorming`, `systematic-debugging`, `dispatching-parallel-agents`, `verification-before-completion`, `executing-plans`, `subagent-driven-development`, `requesting-code-review`, `receiving-code-review`, `using-git-worktrees`, `writing-plans` и `writing-skills` удалили разделы Bottom Line / Key Principles / Real-World Impact / Advantages. `using-git-worktrees` и `finishing-a-development-branch` преобразовали защитные разделы в принятую таблицу рационализаций Excuse/Reality.

### Разработка с субагентами

Длительные эксперименты стоимости и качества на реальных проектах изменили проверку отдельных задач. Ранее работали два проверяющих на задачу, а выбор модели и оценка важности зависели от контроллера; оба подхода оказались дорогими и уязвимыми к обходу. Новый процесс использует одного проверяющего, передаёт материалы файлами вместо вставленного текста и снимает с контроллера часть решений.

- **Один проверяющий задачи, два вывода.** `task-reviewer-prompt.md` один раз читает diff и возвращает соответствие спецификации и оценку качества; одна волна исправлений закрывает оба вида замечаний. Новый вывод «невозможно проверить по diff» отмечает требования в неизменённом коде, которые контроллер должен проверить сам. (#1538, #1543)
- **Одна широкая проверка в конце.** Процесс завершается единым ревью всей ветки на наиболее сильной модели вместо повторения общего ревью для каждой задачи.
- **Предварительное чтение плана.** До первой задачи контроллер проверяет план на внутренние противоречия и требования, которые проверяющий назвал бы дефектами, и сообщает всё сразу, а не обнаруживает проблемы по одной в процессе.
- **Diff и текст задач передаются файлами.** Вставленный diff постоянно занимает самый дорогой контекст; без готового diff проверяющий создаёт его вручную, что даёт наибольшие расходы ревью. Новые `task-brief` и `review-package` записывают текст задачи и diff в файлы для чтения субагентом.
- **В каждом запуске указана модель.** Когда контроллеры перестали явно её выбирать, наследовалась самая дорогая модель сеанса; в одном запуске все 26 проверяющих оказались на высшем уровне. Шаблоны теперь требуют указания модели и рекомендуют более дешёвые уровни, когда задача позволяет.
- **Контроллер не может указывать проверяющему, что игнорировать.** В реальных запусках контроллеры склоняли проверяющих пропустить замечание или признать его не выше Minor, и дефект попадал в результат. Подавление замечаний и предварительная оценка важности запрещены; дефект, прямо предписанный планом, передаётся пользователю для решения.
- **Проверяющие работают только на чтение и критически относятся к объяснениям.** Ревью больше не меняет рабочее дерево и ветку: `git checkout` проверяющего раньше оставлял последующие коммиты без ветки. Объяснение исполнителя «я намеренно не выделил общий код» больше не отменяет обоснованное замечание.
- **Усилены доказательства и отчёты.** Проверяющие подтверждают ответы файлом и строкой; отчёт исполнителя сохраняется в файл и содержит результаты RED/GREEN при применении TDD; журнал прогресса позволяет восстановиться после потери контекста вместо повторного выполнения завершённой работы. (#994)

### Составление планов

Планы включают структуру, которую контроллер и проверяющие раньше заново определяли при каждом запуске:

- **Global Constraints:** дословный перечень общих правил — минимальные версии, ограничения зависимостей, имена, тексты и точные значения — чтобы они доходили до исполнителей и проверяющих.
- **Interfaces для каждой задачи:** точные входы и выходы, позволяющие исполнителю, видящему только свою задачу, понимать контракты соседних.
- **Подходящий размер задачи:** каждая задача заслуживает собственного тестового цикла и ревью; настройка, конфигурация и документация объединяются с задачей, которой они нужны. В тестах такой план потребовал одной волны исправлений против двух–четырёх в контроле; в контрольном результате также осталась реальная ошибка.

### Визуальный помощник brainstorming

Визуальный помощник — небольшой веб-сервер рядом с разговором. Ранее аутентификации не было: на общем или удалённом компьютере любой, кто достигал порта, мог прочитать обсуждение или подставить события, воспринимаемые агентом как ввод пользователя. В выпуске добавлена модель безопасности и восстановление после перезапусков и обрывов соединения.

- **Все запросы защищены ключом сеанса.** URL агента содержит одноразовый ключ; браузер сохраняет его в cookie вкладки, и каждый запрос и WebSocket-соединение должны предъявить ключ. Это защищает от посторонних локальных вкладок и доступных удалённых узлов, включая DNS-rebinding, который не всегда обнаруживает список разрешённых источников. Закрывает #1014.
- **Файловый сервер не выходит за пределы каталога.** Он отклоняет символические ссылки, скрытые файлы и пути за пределы каталога содержимого, игнорирует файлы ресурсных вилок macOS и отправляет заголовки запрета кеширования и встраивания. Файлы ключа доступны только владельцу.
- **Помощник предлагается, только когда полезен.** Навык предлагает его отдельным сообщением при первом вопросе, который лучше показать, чем описать, и уважает отказ. Согласие открывает первый экран в браузере. Закрывает #755.
- **Перезапуски и обрывы соединения поддерживаются.** При указании каталога проекта сервер сохраняет порт и ключ после перезапуска, а открытая вкладка подключается снова. Страница сама восстанавливает соединение, показывает индикатор состояния и сообщение о паузе при отключённом сервере.
- **Более долгий простой и безопасная остановка.** Тайм-аут увеличен с 30 минут до четырёх часов; `stop-server.sh` подтверждает принадлежность процесса до отправки сигнала и не завершает посторонний `node` после перезагрузки. (#1703)
- **Усилен запуск Windows:** определение оболочки объединено; для завершения Windows использует тайм-аут простоя, поскольку Node не может отслеживать принадлежность процесса POSIX через MSYS2.

## v5.0.0 (2026-03-09)

### Breaking Changes

**Specs and plans directory restructured**

- Specs (brainstorming output) now save to `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`

- User preferences for spec/plan locations override these defaults
- All internal skill references, test files, and example paths updated to match
- Migration: move existing files from `docs/plans/` to new locations if desired

**Subagent-driven development mandatory on capable harnesses**

Writing-plans no longer offers a choice between subagent-driven and executing-plans. On harnesses with subagent support (Claude Code, Codex), subagent-driven-development is required. Executing-plans is reserved for harnesses without subagent capability, and now tells the user that Superpowers works better on a subagent-capable platform.

**Executing-plans no longer batches**

Removed the "execute 3 tasks then stop for review" pattern. Plans now execute continuously, stopping only for blockers.

**Slash commands deprecated**

`/brainstorm`, `/write-plan`, and `/execute-plan` now show deprecation notices pointing users to the corresponding skills. Commands will be removed in the next major release.

### New Features

**Visual brainstorming companion**

Optional browser-based companion for brainstorming sessions. When a topic would benefit from visuals, the brainstorming skill offers to show mockups, diagrams, comparisons, and other content in a browser window alongside terminal conversation.

- Brainstorming skill adds a visual companion decision point to its process flow: after exploring project context, the skill evaluates whether upcoming questions involve visual content and offers the companion in its own message
- Per-question decision: even after accepting, each question is evaluated for whether browser or terminal is more appropriate
- Integration tests in `tests/brainstorm-server/`

**Document review system**

Automated review loops for spec and plan documents using subagent dispatch:

- `skills/brainstorming/spec-document-reviewer-prompt.md` — Reviewer checks completeness, consistency, architecture, and YAGNI
- `skills/writing-plans/plan-document-reviewer-prompt.md` — Reviewer checks spec alignment, task decomposition, file structure, and file size
- Brainstorming dispatches spec reviewer after writing the design doc
- Writing-plans includes chunk-based plan review loop after each section
- Review loops repeat until approved or escalate after 5 iterations
- End-to-end tests in `tests/claude-code/test-document-review-system.sh`
- Design spec and implementation plan in `docs/superpowers/`

**Architecture guidance across the skill pipeline**

Design-for-isolation and file-size-awareness guidance added to brainstorming, writing-plans, and subagent-driven-development:

- **Brainstorming** — New sections: "Design for isolation and clarity" (clear boundaries, well-defined interfaces, independently testable units) and "Working in existing codebases" (follow existing patterns, targeted improvements only)
- **Writing-plans** — New "File Structure" section: map out files and responsibilities before defining tasks. New "Scope Check" backstop: catch multi-subsystem specs that should have been decomposed during brainstorming
- **SDD implementer** — New "Code Organization" section (follow plan's file structure, report concerns about growing files) and "When You're in Over Your Head" escalation guidance
- **SDD code quality reviewer** — Now checks architecture, unit decomposition, plan conformance, and file growth
- **Spec/plan reviewers** — Architecture and file size added to review criteria
- **Scope assessment** — Brainstorming now assesses whether a project is too large for a single spec. Multi-subsystem requests are flagged early and decomposed into sub-projects, each with its own spec → plan → implementation cycle

**Subagent-driven development improvements**

- **Model selection** — Guidance for choosing model capability by task type: cheap models for mechanical implementation, standard for integration, capable for architecture and review
- **Implementer status protocol** — Subagents now report DONE, DONE_WITH_CONCERNS, BLOCKED, or NEEDS_CONTEXT. Controller handles each status appropriately: re-dispatching with more context, upgrading model capability, breaking tasks apart, or escalating to human

### Fixed

**Windows: Restored polyglot wrapper for reliable hook execution (#518, #504, #491, #487, #466, #440)**

Claude Code's `.sh` auto-detection on Windows was prepending `bash` to the hook command, breaking execution. The fix:

- Renamed `session-start.sh` to `session-start` (extensionless) so auto-detection doesn't interfere
- Restored `run-hook.cmd` polyglot wrapper with multi-location bash discovery (standard Git for Windows paths, then PATH fallback)

- On Unix, the wrapper runs the script directly via `exec bash`
- Uses POSIX-safe `dirname "$0"` path resolution (works on dash/sh, not just bash)

This fixes SessionStart failures on Windows with spaces in paths, missing WSL, `set -euo pipefail` fragility on MSYS, and backslash mangling.

## v4.2.0 (2026-02-05)

### Breaking Changes

**Codex: Replaced bootstrap CLI with native skill discovery**

The `superpowers-codex` bootstrap CLI, Windows `.cmd` wrapper, and related bootstrap content file have been removed. Codex now uses native skill discovery via `~/.agents/skills/superpowers/` symlink, so the old `use_skill`/`find_skills` CLI tools are no longer needed.

Installation is now just clone + symlink (documented in INSTALL.md). No Node.js dependency required. The old `~/.codex/skills/` path is deprecated.

### Fixes

**Windows: Fixed Claude Code 2.1.x hook execution (#331)**

Claude Code 2.1.x changed how hooks execute on Windows: it now auto-detects `.sh` files in commands and prepends `bash`. This broke the polyglot wrapper pattern because `bash "run-hook.cmd" session-start.sh` tries to execute the `.cmd` file as a bash script.

Fix: hooks.json now calls session-start.sh directly. Claude Code 2.1.x handles the bash invocation automatically. Also added .gitattributes to enforce LF line endings for shell scripts (fixes CRLF issues on Windows checkout).

**Windows: SessionStart hook runs async to prevent terminal freeze (#404, #413, #414, #419)**

The synchronous SessionStart hook blocked the TUI from entering raw mode on Windows, freezing all keyboard input. Running the hook async prevents the freeze while still injecting superpowers context.

**Windows: Fixed O(n^2) `escape_for_json` performance**

The character-by-character loop using `${input:$i:1}` was O(n^2) in bash due to substring copy overhead. On Windows Git Bash this took 60+ seconds. Replaced with bash parameter substitution (`${s//old/new}`) which runs each pattern as a single C-level pass — 7x faster on macOS, dramatically faster on Windows.

**Codex: Fixed Windows/PowerShell invocation (#285, #243)**

- Windows doesn't respect shebangs, so directly invoking the extensionless `superpowers-codex` script triggered an "Open with" dialog. All invocations now prefixed with `node`.
- Fixed `~/` path expansion on Windows — PowerShell doesn't expand `~` when passed as an argument to `node`. Changed to `$HOME` which expands correctly in both bash and PowerShell.

**Codex: Fixed path resolution in installer**

Used `fileURLToPath()` instead of manual URL pathname parsing to correctly handle paths with spaces and special characters on all platforms.

**Codex: Fixed stale skills path in writing-skills**

Updated `~/.codex/skills/` reference (deprecated) to `~/.agents/skills/` for native discovery.

### Improvements

**Worktree isolation now required before implementation**

Added `using-git-worktrees` as a required skill for both `subagent-driven-development` and `executing-plans`. Implementation workflows now explicitly require setting up an isolated worktree before starting work, preventing accidental work directly on main.

**Main branch protection softened to require explicit consent**

Instead of prohibiting main branch work entirely, the skills now allow it with explicit user consent. More flexible while still ensuring users are aware of the implications.

**Simplified installation verification**

Removed `/help` command check and specific slash command list from verification steps. Skills are primarily invoked by describing what you want to do, not by running specific commands.

**Codex: Clarified subagent tool mapping in bootstrap**

Improved documentation of how Codex tools map to Claude Code equivalents for subagent workflows.

- Added worktree requirement test for subagent-driven-development
- Added main branch red flag warning test
- Fixed case sensitivity in skill recognition test assertions

# Superpowers v2.0.0 Release Notes

## Overview

Superpowers v2.0 makes skills more accessible, maintainable, and community-driven through a major architectural shift.

The headline change is **skills repository separation**: all skills, scripts, and documentation have moved from the plugin into a dedicated repository ([obra/superpowers-skills](https://github.com/obra/superpowers-skills)). This transforms superpowers from a monolithic plugin into a lightweight shim that manages a local clone of the skills repository. Skills auto-update on session start. Users fork and contribute improvements via standard git workflows. The skills library versions independently from the plugin.

Beyond infrastructure, this release adds nine new skills focused on problem-solving, research, and architecture. We rewrote the core **using-skills** documentation with imperative tone and clearer structure, making it easier for Claude to understand when and how to use skills. **find-skills** now outputs paths you can paste directly into the Read tool, eliminating friction in the skills discovery workflow.

Users experience seamless operation: the plugin handles cloning, forking, and updating automatically. Contributors find the new architecture makes improving and sharing skills trivial. This release lays the foundation for skills to evolve rapidly as a community resource.

## Breaking Changes

### Skills Repository Separation

**The biggest change:** Skills no longer live in the plugin. They've been moved to a separate repository at [obra/superpowers-skills](https://github.com/obra/superpowers-skills).

**What this means for you:**

- **First install:** Plugin automatically clones skills to `~/.config/superpowers/skills/`
- **Forking:** During setup, you'll be offered the option to fork the skills repo (if `gh` is installed)
- **Updates:** Skills auto-update on session start (fast-forward when possible)
- **Contributing:** Work on branches, commit locally, submit PRs to upstream
- **No more shadowing:** Old two-tier system (personal/core) replaced with single-repo branch workflow

**Migration:**

If you have an existing installation:
1. Your old `~/.config/superpowers/.git` will be backed up to `~/.config/superpowers/.git.bak`
2. Old skills will be backed up to `~/.config/superpowers/skills.bak`
3. Fresh clone of obra/superpowers-skills will be created at `~/.config/superpowers/skills/`

### Removed Features

- **Personal superpowers overlay system** - Replaced with git branch workflow
- **setup-personal-superpowers hook** - Replaced by initialize-skills.sh

## Upgrade Instructions

### Fresh Install

```bash
# In Claude Code
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace
```

The plugin handles everything automatically.

### Upgrading from v1.x

1. **Backup your personal skills** (if you have any):
   ```bash
   cp -r ~/.config/superpowers/skills ~/superpowers-skills-backup
   ```

2. **Update the plugin:**
   ```bash
   /plugin update superpowers
   ```

3. **On next session start:**
   - Old installation will be backed up automatically
   - Fresh skills repo will be cloned
   - If you have GitHub CLI, you'll be offered the option to fork

4. **Migrate personal skills** (if you had any):
   - Create a branch in your local skills repo
   - Copy your personal skills from backup
   - Commit and push to your fork
   - Consider contributing back via PR
