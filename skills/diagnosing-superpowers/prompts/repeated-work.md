Сначала прочитай `prompts/analyst-common.md`: там указаны роль, входные данные, правила безопасности контекста и формат ответа. Этот файл дополняет их направлением анализа.

Направление: повторная работа

Найди работу, выполненную в сессии более одного раза.

1. Извлеки каждый вызов инструмента как `(line, turn, tool, key)`. Ключ: путь файла для чтения, изменения и записи; полный текст команды оболочки без завершающих пробелов; `description` и первые 80 символов запроса при запуске субагента; запрос при поиске.
2. Сгруппируй по `(tool, key)` и сообщи группы, достигшие порога:

   | Категория | Порог | Исключения |
   |---|---|---|
   | чтение, поиск | 3 | |
   | изменения | 2 | |
   | команды оболочки | 2 | проверки состояния и тесты: `git status`, `ls`, `pwd`, запускатели тестов |
   | запуск субагентов | 2 с одинаковым описанием | |
3. Для каждой группы проверь, что изменилось между повторами: запись в файл, сжатие контекста, исправление человека. Укажи случай. Повторное чтение после изменения не является находкой; после сжатия — находка, отнесённая к нему; без промежуточных изменений — самостоятельная находка.
4. Найди заново выведенные решения: ассистент повторно приходит к ранее сформулированному выводу о том же файле, проектном решении или команде. Процитируй оба места.
5. Один вывод на группу: первая и последняя строки и число повторений.
