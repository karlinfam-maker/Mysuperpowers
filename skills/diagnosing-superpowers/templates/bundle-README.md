# Комплект диагностики сессии Superpowers

Session: <session-id>
Harness: <name> <version> (<provenance label>)    Superpowers: <version> (<sha or "not a checkout">; <provenance label>)
Redaction level: skeleton | evidence | full
Built: <ISO timestamp>

Для версий в заголовке укажи происхождение: историческое доказательство, непроверенный снимок, текущее наблюдение или неизвестно. Файл `environment.json` содержит те же различия и источник для каждого поля окружения.

## Что это

Очищенная запись сессии агента разработки, в которой был установлен Superpowers и возникла проблема. Она позволяет человеку или агенту, не участвовавшему в сессии, оценить возможную причастность Superpowers и необходимые изменения. Отчёт описывает произошедшее с доказательствами `path:line`. По замыслу он не содержит диагноза Superpowers и предлагаемого исправления: это задача читателя.

## Файлы

- `report.md` — отчёт диагностики: постановка, вывод, окружение, сессии, хронология, находки, причастность и охват.
- `case.md` — файл случая, по которому работали аналитики.
- `environment.json` — машиночитаемая копия сведений об окружении.
- `timeline.md` — хронология по ходам.
- `findings/<dimension>.md` — исходные выводы аналитиков по направлениям.
- `transcripts/<session-id>.md` — сокращённое представление каждой изученной сессии по ходам; никогда не исходный JSONL. Содержимое ответов инструментов зависит от уровня:

  | Уровень | Содержимое ответов инструментов |
  |---|---|
  | skeleton | намеренно ограничено; заменено на `[tool result: <tool>, <bytes> bytes, exit <code>]` |
  | evidence | сохранено для цитируемых событий, включая необходимые команды и результаты |
  | full | сохранено всё |
- `scrub-log.md` — каждый применённый заменитель и категория, никогда исходное значение.

## Как читать

Начни с разделов 1–2 `report.md`, затем раздела 7 о причастности и указанных доказательств, после — соответствующих ходов в `transcripts/`. Ссылки `path:line` указывают на оригинальные файлы компьютера автора отчёта; те же номера строк сохранены в сокращённых записях маркерами `[L<n>]`.

## Очистка

Заменители имеют вид `<EMAIL-1>`, `<PERSON-2>`, `<SECRET-3>`, `<HOST-4>`, `<REPO-5>`, `<ORG-6>`, `<PROPRIETARY-7>`; домашние пути превращаются в `~/…`. В пределах комплекта один заменитель всегда соответствует одному исходному значению.

## Инструкции составителю

В готовом комплекте эти инструкции заменяются фактическими результатами.

После очистки проверь каждый существенный экспортируемый вывод только по комплекту: найди его ссылку в приложенной записи или маркере источника, прочитай указанную команду, результат или цитату и установи, подтверждает ли она утверждение. Одного существования пути и строки недостаточно. Если уровень очистки или необходимое исключение данных удаляет доказательство, зафиксируй конкретное ограничение.

Сверь отчёт, файл случая, окружение, выводы, README и локальный черновик обращения. Обнови количества в журнале очистки по итоговым файлам, не считая сам журнал. Убери устаревшие заявления об экспорте; различай подготовку комплекта и передачу архива. Сохрани связь исторических ссылок с включёнными доказательствами.

Независимую проверку конфиденциальности фиксируй отдельно от пригодности доказательств:
- Проверка конфиденциальности: CLEAN или нерешённые пропуски.
- Подтверждение доказательствами: подтверждено или ограничено с указанием затронутых выводов и причин.

При изменении содержимого повтори затронутые проверки. Покажи итоговый журнал, список файлов и оба результата перед предусмотренным согласованием архива. Архивируй проверенные файлы и убедись, что переданный архив им соответствует. Факт передачи зафиксируй вне проверенного комплекта, не меняя его после согласования. Очистка не является исчерпывающей сертификацией конфиденциальности.
