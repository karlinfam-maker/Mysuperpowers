## Для запуска субагентов нужна поддержка нескольких агентов

Добавь в конфигурацию Codex (`~/.codex/config.toml`):

```toml
[features]
multi_agent = true
```

Это включает инструменты, используемые навыками `dispatching-parallel-agents` и `subagent-driven-development`. Доступные инструменты зависят от версии механизма, выбранной моделью: текущие настройки используют V2, старые — V1. При расхождении ориентируйся на фактически доступный список инструментов, а не на таблицу или этот документ. Соблюдай указания пользователя и среды о допустимости делегирования.

- **Запуск:** передавай дочерним агентам чистый контекст через `spawn_agent {fork_turns: "none"}`; значение по умолчанию `"all"` копирует всю историю сессии. В Codex 0.145+ файлы ролей в `~/.codex/agents/` подключаются к изолированным ответвлениям через `agent_type`. Ответвления с полной историей принимают переопределения `model` и `reasoning_effort`, но не `agent_type`. Изоляция по умолчанию в SDD нужна для чистоты контекста, а не для переопределений.
- **Раунды исправлений:** продолжай работу с исполнителем через `followup_task`: команда доставляет сообщение, запускает новый ход и при необходимости прозрачно загружает ранее выгруженного агента. Не запускай нового исполнителя из предположения, что прежнему больше нельзя написать: в V2 это возможно.
- **Жизненный цикл:** в V2 нет `close_agent`. Завершённые агенты автоматически выгружаются, когда требуются свободные места; оставлять их открытыми не затратно. `close_agent` есть только в V1: там закрывай проверяющих после отчёта, а исполнителей — после успешной проверки задачи.
- **Названия моделей:** не копируй имя модели из навыка, таблицы или старой сессии в `spawn_agent`, не сверив с текущим списком разрешённых моделей. V2 принимает только совместимые варианты и выдаёт ошибку для остальных.

## Ожидание дочерних агентов

`wait_agent` — подписка на событие, а не периодический опрос: длительное ожидание завершается сразу при активности агента, с той же задержкой, что и короткое. Частые короткие ожидания не ускоряют работу, но расходуют вызовы и повторно обрабатывают контекст. В наблюдавшихся сессиях около двух третей ожиданий были короткими опросами без результата.

- Пока есть местная работа, не ожидай. Итоговый ответ завершившегося агента поступит в почту и появится на следующем ходе.
- Когда работы нет, а агенты ещё выполняют задачи, ожидай ограниченными интервалами: `wait_agent` с `timeout_ms` 300000–600000, если платформа допускает. После каждого интервала — результата или тайм-аута — дай короткий статус, вызови `list_agents` и проверь агентов, завершившихся без отчёта. Не запускай цепочку коротких опросов: подписка разбудит длительное ожидание столь же быстро. Соблюдай также ограничения ожидания текущей среды.
- Сообщение о завершении само по себе не запускает ход бездействующего координатора; это окно и покрывает `wait_agent`. Тайм-аут без событий — повод сверить состояние, а не сокращать следующий интервал.

## Выбор модели при запуске

Исходный документ предлагает для каждого `spawn_agent` задавать и `model`, и `reasoning_effort` по правилам используемого навыка. Указание только модели может сбросить уровень рассуждения к значению модели по умолчанию. Используй переопределения только если это разрешено текущими инструкциями и списком доступных моделей.

В качестве необязательного резервного механизма исходный документ предлагает спросить пользователя о настройке `~/.codex/config.toml`, чтобы пропущенный выбор модели не приводил к использованию самой дорогой модели сессии:

```toml
[agents]
default_subagent_model = "<a mid-tier model from your spawn allowlist>"
default_subagent_reasoning_effort = "medium"
```

## Определение окружения

Навыки создания worktree и завершения веток должны сначала проверить окружение командами git только для чтения:

```bash
GIT_DIR=$(cd "$(git rev-parse --git-dir)" 2>/dev/null && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" 2>/dev/null && pwd -P)
BRANCH=$(git branch --show-current)
```

- `GIT_DIR != GIT_COMMON` → уже находишься в связанном worktree; не создавай ещё один.
- `BRANCH` пуст → HEAD отсоединён; операции с веткой, push или PR могут быть недоступны в песочнице.

См. шаг 0 `using-git-worktrees` и шаг 1 `finishing-a-development-branch`, чтобы узнать, как навыки используют эти признаки.

## Завершение в приложении Codex

Если песочница блокирует операции с веткой или push при отсоединённом HEAD в рабочей области, управляемой извне, агент создаёт коммит и сообщает пользователю о встроенных элементах приложения:

- **Create branch** — создать ветку, затем выполнить commit, push и PR через интерфейс.
- **Hand off to local** — передать работу в локальную копию пользователя.

Агент по-прежнему может запускать тесты, подготавливать файлы к коммиту и предложить название ветки, сообщение коммита и описание PR.
