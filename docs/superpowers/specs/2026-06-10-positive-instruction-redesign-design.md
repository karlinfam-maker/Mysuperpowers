# Переработка инструкций навыков в позитивные формулировки — спецификация

**Статус:** предложено как продолжение работы по отправке проверок SDD от 2026-06-09; отдельный PR согласно правилу «одна проблема — один PR».
**Основание:** измерения 2026-06-10 показывают, что некоторые запретительные инструкции в тексте навыков дают обратный эффект, другие работают, а различие можно предсказать.

## Результат измерений, который обобщает спецификация

Микротесты 2026-06-10 (opus, пять повторов каждой формулировки, программная оценка; метод описан ниже) измеряли, как формулировка указаний влияет на результат контроллера:

| Ситуация | Формулировка | Результат |
|---|---|---|
| Составление запроса проверяющему: «не пересказывай задание» | Запрет | Повторно набрано **4,4** значения спецификации — *хуже, чем без указаний* (3,6) |
| Составление запроса | Позитивный рецепт: «запрос должен содержать: (1)…(5)» | **3,0, без разброса** — принято |
| Составление запроса | Рецепт и уточнение: «цитируй только фрагмент…» | 3,8, с разбросом — уточнение ослабляет рецепт |
| Повторный запуск тестов: «не проси проверяющего повторно запускать тесты» | Запрет | **0 нарушений из 5** — работает; в контроле 3 из 5 |
| Повторный запуск тестов | Позитивный рецепт | 0 из 5 — так же, но длиннее |

**Принцип для классификации запретов:**

1. **Сигналы срабатывают.** Самопроверки по конкретным словам, например «если в запросе есть “do not flag” — остановись», надёжно запускают нужную реакцию.
2. **Таблицы распознавания работают.** Таблицы тревожных признаков и рационализаций читаются в момент принятия решения, а не составления текста.
3. **Запреты отдельных действий работают.** «Не проси X сделать Y» соблюдается, когда у модели нет конкурирующего стимула выполнить Y.
4. **Запреты при составлении текста дают обратный эффект**, когда у модели есть собственный стимул к результату — например, пересказ спецификации кажется полезной систематизацией. Результат меняет только позитивный рецепт; добавление уточнений к удачному рецепту ухудшает его.
5. **При равном результате выигрывает короткая формулировка.** Согласно измерениям 2026-06-10, Codex перечитывает SKILL.md около 500 раз за длинный сеанс; объём текста имеет реальную стоимость.

## Изменение writing-plans — отложенный пункт 5

### Текущее состояние

В `skills/writing-plans/SKILL.md`, в разделе «No Placeholders», одно позитивное предложение («каждый шаг должен содержать фактическую информацию, необходимую инженеру») сопровождается списком из шести запрещённых шаблонов: `TBD`, `TODO`, «Add appropriate error handling», «Write tests for the above», «Similar to Task N» и других.

### Почему это важно и почему результат неочевиден

- Планы — **крупнейший создаваемый материал** рабочего процесса. У модели есть конкурирующий стимул использовать заглушки, поскольку при ограничении длины это требует меньше усилий; в похожем случае запрет измеримо ухудшил результат.
- Однако запрещённые элементы — **конкретные распознаваемые выражения**, а в ситуации такого типа запрет измеримо сработал.
- **Список используется и в другом месте:** раздел самопроверки навыка требует искать в плане признаки из раздела «No Placeholders». Выражения одновременно служат перечнем для проверки, а распознавание при проверке относится к работающим механизмам. Простая замена позитивным контрольным списком сломала бы ссылку и убрала полезные сигнальные выражения.

### Варианты для проверки

- **V0 — текущий:** позитивное предложение и список запретов при составлении; самопроверка ссылается на список.
- **V1 — контрольный список аудитора:** при составлении только позитивный рецепт: перед завершением шага проверить наличие конкретного кода, запускаемой команды с ожидаемым выводом, определённых в плане типов и имён методов, а также явно показанной обработки ошибок. Шаг завершён, когда инженер может реализовать его без дополнительных вопросов. В самопроверке остаётся общая проверка заглушек.
- **V2 — перестройка по механизму, предполагаемый победитель:** при составлении остаётся позитивный рецепт V1; перечисленные шаблоны полностью переносятся в шаг самопроверки и формулируются как признаки для поиска: `TBD`, `TODO`, `Similar to Task N` и другие. Те же выражения перемещаются из категории, которая может провоцировать поведение, в категорию обнаружения.
- **V3 — контроль:** только позитивное предложение, без списков.

### Устройство микротеста

- **Задача:** opus пишет план реализации из 2–3 задач по намеренно недостаточно подробной спецификации: неполнота провоцирует заглушки. Тестовая спецификация содержит одну подробно описанную задачу, одну с расплывчатой обработкой ошибок и одну похожую на первую, провоцирующую «Similar to Task 1».
- **Выборка:** не менее пяти повторов каждого варианта, температура по умолчанию, модель `claude-opus-4-8`, используемая на практике для планов.
- **Программная оценка:** меньше — лучше, кроме специально указанного показателя:
  - количество запрещённых выражений: `TBD|TODO|implement later|fill in details|appropriate error handling|handle edge cases|Similar to Task|Write tests for the above`;
  - число шагов без блока кода с ограждением, когда шаг меняет код;
  - ссылки на типы или функции, нигде не определённые в плане;
  - количество запускаемых команд с ожидаемым выводом на задачу — больше означает лучше.
- **Двухэтапная оценка V2:** проверить и самопроверку. Передать каждый созданный план обратно с разделом самопроверки соответствующего варианта и измерить обнаружение намеренно добавленных заглушек: вставить две известные заглушки в тестовый план; метрика — доля обнаружений.
- **Приёмка:** принимать вариант, только если он превосходит V0 по числу запрещённых выражений и при этом не ухудшает покрытие блоками кода и обнаружение при самопроверке. Ожидаемые затраты — около 6–10 долларов всего.

### Объём PR

Нужен отдельный PR: writing-plans — другой навык, а список «No Placeholders» тщательно настроен и согласно правилам участников требует доказательств оценки. PR должен содержать средство микротестирования и таблицу результатов, текст до и после изменения и обоснование переноса V2.

## Средство микротестирования: метод

`/tmp/sdd-exp/micro/run-micro.py` и `/tmp/sdd-exp/micro2/run-micro2.py` (2026-06-10; планируется сохранить в superpowers-evals как `docs/superpowers/skills/micro-testing-prompt-guidance.md` и скрипты):

- Один вызов API на образец: системный запрос содержит вариант инструкции в реалистичном контексте; пользовательский — реалистичную ситуацию в процессе работы; результат — составленный материал: запрос исполнителю, план или отчёт.
- Программная оценка через поиск однозначных маркеров; **каждое совпадение необходимо проверить вручную до вынесения заключения**. В одном из обнаруженных «нарушений» контроллер правильно цитировал запрет, ещё одно было ошибочно отмечено автоматической проверкой отрицаний.
- Примерно 0,15–0,30 доллара на образец и секунды на итерацию, против 12 долларов за полноценный 50-минутный прогон. Формулировки уточняются микротестами; победителей подтверждают полными прогонами только для структурных изменений.
- Всегда включать контроль без инструкций: в этом случае он показал как обратный эффект — запрет пересказа хуже отсутствия инструкции, — так и работающий запрет повторного запуска тестов: три нарушения из пяти в контроле и ноль из пяти при любой из двух формулировок.

## Результат микротеста writing-plans

Запуск 2026-06-10 после написания спецификации. **Решение: изменения не нужны.** На этапе 1 — спецификация из трёх задач без давления — во всех 20 планах четырёх вариантов, включая контроль без инструкции, заглушек не обнаружено. На этапе 1b — спецификация из десяти задач, пять почти одинаковых команд, провоцирующих «Similar to Task N», и явная цель уложиться примерно в 2500 слов — чистыми оказались все 40 из 40 планов. Единственное совпадение регулярного выражения было подтверждением самопроверки V2: «no TBD/TODO ✓».

Текущая на момент теста версия opus не создаёт заглушек в планах даже при намеренном давлении, как со списком запретов, так и без него. Решение: оставить раздел No Placeholders без изменений — его стоимость невелика, а эффект альтернативы не поддаётся измерению; последующий PR **не открывать**. Идея переноса V2 сохранена на случай ухудшения поведения будущей модели.

## Другие явно отклонённые идеи

Записаны, чтобы не предлагать их вновь без новых данных; полные числа находятся в разделе Cost-iterations спецификации SDD от 2026-06-09:

- **Объединение действий контроллера и параллельные вызовы инструментов в одном сообщении:** контроллер отправляет ровно один вызов инструмента в сообщении; во всех измеренных прогонах с инструкцией и без неё не было сообщений с несколькими вызовами. 46% ходов контроллера приходятся на размышления или комментарии без инструментов — предел, не изменившийся от формулировки запроса.
- **Конвейерные проверки через параллельные вызовы:** не работают по той же причине.
- **Конвейерные проверки через `run_in_background`:** механизм использовался при наличии в 7 из 28 отправок, но выигрыш на 45-минутных сценариях оказался ниже естественного разброса между прогонами; отдельная проверка занимает около 30–60 секунд. При этом требуется координация двух потоков результатов. Возвращаться к идее стоит для планов с длительными отдельными проверками.
- **Уточнения, добавленные к успешным рецептам:** измеримо ухудшают результат: C2 — 3,8 с разбросом против C — стабильные 3,0. При доработке лучше заново сформулировать рецепт, чем добавлять оговорки.
